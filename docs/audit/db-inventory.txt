=== 3. Policies ===
541 policies across 175 tables. 448 target {authenticated}, 93 target {public}.

{public} means "every role including anon". 92 of the 93 still require a login inside
their USING / WITH CHECK (auth.uid() IS NOT NULL, fn_wh_can(), sched_can_write(),
jmr_can_see_project(), or an owner match) - so they are NOT open to anon in practice.

The ONE exception, readable with the anon key and no login:
  sched_promises | sched_promises_select_merged_public | SELECT | {public}
  USING (true OR sched_can_write())   <- evaluates to true for anon
  -> Anyone holding the public anon key can read every row of sched_promises.
     By the pack's own scale (exposed data) this is P0 until judged otherwise.

=== 4. anon table-level grants ===
anon holds DELETE, INSERT, REFERENCES, SELECT, TRIGGER, TRUNCATE, UPDATE on every public
table. This is Supabase's DEFAULT grant and is NOT a finding: with RLS on, a grant does
nothing unless a policy lets the row through. See section 3 for the one that does.
